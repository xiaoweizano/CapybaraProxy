# CapybaraProxy V1 产品需求

## 1. 产品定位

CapybaraProxy 是一款跨平台个人网络代理控制中心。它以 Mihomo 为代理核心，提供配置管理、代理组和节点选择、规则管理、连接监控、流量统计、日志和系统代理/TUN 管理。

产品不是传统 Clash 客户端的换皮。品牌识别来自 CapybaraProxy 波纹 Logo、A 主题 Network Orb、C 主题吉祥物，以及可定制的网络工作台。

## 2. 目标平台

- Windows
- macOS
- Linux
- Android

桌面端与 Android 使用不同的原生系统集成方式。第一版不承诺 iOS。

## 3. 核心原则

- 视觉体验：A/C 双主题，默认 A。
- 功能一致：主题只改变视觉，不改变功能和数据。
- 资源优先：低空闲 CPU、低后台开销、合理内存占用。
- 安全可靠：代理核心生命周期、系统代理和 TUN 状态必须可观察、可恢复。
- 可维护：UI、Runtime、Mihomo 和平台适配层边界清楚。
- 不伪造状态：未连接、未知、加载中、错误必须明确区分。

## 4. V1 功能范围

### P0：首个可用版本必须具备

1. 首次启动引导与基础设置。
2. 导入、查看、启用和删除配置/订阅（订阅更新策略需后续细化）。
3. Mihomo 核心版本与运行状态展示。
4. 启动、停止、重启 Mihomo；崩溃检测和错误提示。
5. Overview 首页：
   - 连接状态 / Network Orb
   - 上传、下载实时速率
   - Proxy Group
   - 当前节点选择
   - 延迟测试与延迟展示
   - 流量统计
   - 活跃连接数量
   - 系统/核心状态
6. Proxies：代理组、节点列表、当前选择、延迟测试。
7. Rules：规则查看和规则模式展示；编辑能力按 V1 范围评估。
8. Connections：连接列表、搜索/筛选、关闭单条连接（需确认 Mihomo API 能力）。
9. Profiles：配置导入、切换、更新状态。
10. Logs：核心日志查看、级别/关键字筛选、复制和清理展示缓存。
11. Settings：主题、关闭窗口行为、开机启动（平台允许时）、核心路径/版本、系统代理/TUN 等设置。
12. 系统托盘：显示窗口、连接/断开、当前状态、退出。
13. 桌面 A/C 主题；Android A/C 主题。
14. 配置与 UI 偏好持久化。

### P1：V1.1 或后续

- 工作台组件拖拽、显隐、尺寸调整和布局保存。
- 多工作台布局模板。
- 多窗口。
- 节点地图高级交互。
- 更丰富的流量历史图表。
- 吉祥物动作/表情状态扩展。
- 规则编辑器和高级配置编辑器。
- AI 辅助配置（仅在明确授权和设计后加入）。

## 5. 关键行为约定

### 关闭窗口

默认 `close_window_behavior = "minimize_to_tray"`：
- 点击窗口关闭按钮时隐藏主窗口，不退出进程。
- Mihomo 保持运行，当前代理状态不变。
- 托盘菜单可重新打开窗口。
- 用户可在 Settings 中选择 `exit_application`。
- 退出时按受控流程停止核心并清理由应用创建的临时资源。
- 关闭窗口与托盘“退出”必须是两个不同动作。

### 主题

默认 `theme = "cyber_flow"`。可选 `warm_flow`。
- 桌面和 Android 均支持。
- 选择持久化。
- 不因主题切换重启 Mihomo。
- 不修改节点、配置、连接状态或布局数据。
- 首次启动可跟随系统主题的行为不作为默认；V1 默认 A。

### 连接状态

至少区分：
- `stopped`
- `starting`
- `running_disconnected`
- `connected`
- `stopping`
- `error`
- `permission_required`

UI 不得仅通过动画颜色推断连接状态，必须由 Runtime 状态驱动。

## 6. 非功能需求

- 空闲时尽可能接近零 CPU；不活动页面停止无意义轮询。
- UI 不得因流量数据高频变化而整页刷新。
- 核心进程必须可独立监控、重启和安全退出。
- 敏感配置、订阅 URL、代理凭据不得写入普通日志。
- 所有平台特有能力必须有明确的支持状态和失败原因。
- 应用崩溃或窗口关闭不能留下无法解释的系统代理/TUN 状态。
