# 性能与资源要求

## 1. 优先级

1. 代理连接稳定和系统状态正确。
2. 后台常驻资源占用低。
3. 前台交互流畅。
4. 动效和装饰效果。

不能为了视觉效果牺牲代理稳定性或后台资源。

## 2. 资源策略

### CPU
- 空闲时停止无意义轮询。
- 使用事件驱动优先于高频轮询。
- UI 不可见时降低流量采样和渲染频率。
- 稳定状态 Orb 动画降频或暂停。
- 图表只绘制可见窗口内需要的数据点。

### Memory
- 页面按需加载。
- 日志和连接列表采用分页/上限缓存。
- 流量历史采用环形缓冲区或有界队列。
- 及时释放订阅、事件监听和定时任务。
- 避免重复持有完整 Mihomo 配置和日志副本。

### IPC
- 高频状态合并/节流。
- 仅向订阅者发送必要字段。
- 不把每个流量采样点都转成全局 React 状态。

### Animation
- 支持系统减少动态效果。
- 后台隐藏窗口时暂停装饰动画。
- 动画使用 transform/opacity 等较低成本属性。
- 避免大面积持续 blur、滤镜和全屏粒子。

## 3. 性能测量场景

每个平台至少测量：
1. 冷启动到首页可交互。
2. 首页空闲 5 分钟。
3. 代理连接稳定 5 分钟。
4. 流量持续变化 5 分钟。
5. 主窗口隐藏到托盘 10 分钟。
6. 打开 Connections 和 Logs 大数据列表。
7. 切换 A/C 主题。
8. Mihomo 重启和异常退出恢复。

记录：
- CapybaraProxy UI/Rust 进程 CPU、内存。
- Mihomo CPU、内存。
- 整体应用 CPU、内存。
- 空闲后台唤醒/轮询频率。
- 启动耗时、交互响应和异常情况。

## 4. 初步目标

- 隐藏窗口且核心稳定运行时，UI 不应持续高频重绘。
- 空闲 UI CPU 目标平均低于 1%，以测试设备和测量窗口为准。
- 后台装饰动画为 0。
- 运行中的 Mihomo 实例数量为 1。
- 内存预算在 POC 设备实测后确定，不在未测试前承诺绝对数值。

## 5. 性能报告模板

每次测试记录设备、操作系统版本、构建版本、测试场景、持续时间、UI CPU/内存、Mihomo CPU/内存、总占用、问题和优化前后对比。
