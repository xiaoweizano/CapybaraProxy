# 首页组件与交互规格

## 1. 桌面导航

顺序：
1. Overview
2. Proxies
3. Rules
4. Connections
5. Profiles
6. Logs
7. Settings

导航栏固定在左侧。当前页面具有明显选中态。图标风格统一，标签清晰。

## 2. Overview 核心组件

### Connection Hero
- A：Network Orb。
- C：吉祥物。
- 展示连接状态、运行时长（若可准确获得）、上传速率、下载速率。
- 状态来源于 Runtime，不允许 mock 数据混入正式运行模式。

### Proxy Group
- 展示当前代理组。
- 可打开选择列表。
- 选择结果需调用 Runtime/Mihomo API，并在确认成功后更新 UI。

### Current Node
- 展示节点名称、国家/地区标识（数据存在时）。
- 允许选择节点。
- 节点切换需显示加载、成功或失败反馈。

### Latency
- 展示延迟数值和单位。
- 未测试/测试失败时显示明确状态，不得用随机延迟。

### Traffic Chart
- 展示实时上传/下载趋势。
- 高频数据独立于常规 React 页面状态。
- 控制采样和显示频率；窗口隐藏时降低或停止视觉刷新。

### Node Map
- 展示节点地理分布（只有存在可信地理数据时）。
- 不得伪造节点坐标。
- 地图加载失败不影响代理核心功能。

### Active Connections
- 展示活跃连接数。
- 点击跳转 Connections。
- 数据更新采用节流/合并策略。

## 3. 工作台

V1 先实现参考图规定的固定首页布局。组件拖拽、缩放、多工作台放入 P1，不得为追求自由布局牺牲首屏还原度和资源表现。

## 4. 交互状态

所有异步动作至少具备：
- idle
- loading
- success
- error

按钮在请求过程中防止重复提交。错误提示说明可操作的恢复方法。

## 5. 响应式布局

桌面按参考图比例设计，窗口缩小时优先重排卡片，不允许内容互相覆盖。
Android 使用独立的移动端布局：底部导航或合适的原生导航模式，触控目标满足平台可用性要求。
