# UI 视觉基准与还原要求

## 1. 设计基准

本目录中的两张用户上传图片是 CapybaraProxy V1 的权威视觉参考：

- `assets/design-reference/A.png`
- `assets/design-reference/C.png`

A 图是默认主题，C 图是可切换主题。不要用新的概念稿替代这两张图，也不要把它们理解成仅供灵感参考。

目录中其他历史命名的导出图不作为本阶段的权威基准；如与 `A.png`、`C.png` 不一致，以这两张图为准。

## 2. “一比一还原”的工程解释

目标是尽可能还原：
- 整体构图、侧栏宽度比例、卡片位置和尺寸关系
- 品牌 Logo 与标题位置
- 主视觉区域占比
- 字体层级、间距、圆角、阴影、描边
- 颜色、渐变、光效和图表风格
- 代理组、节点、延迟、地图、连接数等模块的相对关系

不应机械锁死参考图像素。必须适配窗口缩放、不同 DPI、宽高比和 Android 屏幕。保持视觉比例与信息层级优先。

## 3. 首页结构

桌面：
- 左侧固定导航栏
- 顶部窗口标题栏/应用控制区（按平台窗口能力适配）
- 主内容工作区
- 主视觉连接卡片
- 代理组与节点卡片
- 延迟卡片
- 地图/节点分布区域
- 流量和活跃连接信息卡片

Android：
- 保留 A/C 视觉语言、Orb/吉祥物、状态、流量、节点选择等重点。
- 不将桌面侧栏简单缩小。移动端采用适合触控的导航与纵向卡片布局。
- 小屏优先呈现连接状态、流量和当前代理组/节点。

## 4. 禁止事项

- 不得自行换成通用后台管理模板。
- 不得默认采用纯白 SaaS 仪表盘风格。
- 不得用大量无意义渐变和玻璃效果掩盖信息层级。
- 不得将所有卡片做成同一种尺寸和视觉权重。
- 不得在 C 主题中删除吉祥物。
- 不得在 A 主题中用吉祥物替代 Network Orb。
- 不得把真实状态用随机数或假数据伪装。原型阶段可用明确标注的 mock 数据。

## 5. 验收方式

每个关键页面至少提供：
- A 主题截图
- C 主题截图
- 桌面标准尺寸截图
- 桌面窄窗口截图
- Android 常见屏幕截图（进入 Android 阶段后）

与参考图逐项比对构图、颜色、间距和组件。差异必须记录，不得以“风格相似”作为完成标准。
